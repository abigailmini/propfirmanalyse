# PropAnalyse analytics backend (go.propanalyse.com)

Cloudflare Worker + D1 (free tier, nothing to maintain). One Worker does four jobs:

| Route | What |
|---|---|
| `GET /<firm-slug>?src=<page>&pos=<slot>&code=<promo>` | Logs the outbound click, then **302** to the firm's `affiliate_url` if set, else its official `site`. Unknown slug → https://propanalyse.com/. Never strands a visitor: any error still redirects. |
| `POST /e` | Cookieless beacon from `/assets/a.js` (1.3 KB): page views, promo-code copies, other outbound links. |
| `POST /f` | Form intake: complaint, listing, correction, status-review, review (future). Optional e-mail via Resend. |
| `GET /admin` | Dashboard (basic auth, password = secret `ADMIN_TOKEN`, any username), inbox with statuses, CSV export (`/admin/export.csv?t=pageviews|clicks|events|submissions&r=1|7|30|90`). |

Also `/health` (JSON) and `/robots.txt` (disallow all).

## Privacy design
- No cookies, no storage on the device, no raw IPs. `visitor` = sha256(daily random salt | IP | user-agent), 16 hex chars. Salts are random per day, kept in D1 ~48 h, then deleted (cron + on write), so hashes cannot be reversed or linked across days. Hence "visitors" are daily uniques; 7/30-day figures are sums of daily uniques.
- Beacon does not run with Do Not Track or Global Privacy Control; the Worker also drops beacons carrying `DNT: 1` / `Sec-GPC: 1`. Outbound clicks still redirect, and are logged without the visitor hash.
- Country only (Cloudflare `cf.country`), device class only (mobile/tablet/desktop), referrer host only.
- Bot filter (clicks + beacon): crawler/preview/script user-agents (Googlebot, WhatsApp/Telegram/Facebook previews, curl, python, headless Chrome, GPTBot...), `HEAD` requests, missing or `*` Accept-Language, `Sec-Purpose: prefetch`. Bots are still redirected but only counted in `bot_hits` (shown on the dashboard).
- Retention: rows older than `RETENTION_DAYS` (400) deleted by the daily cron.
- Public page: https://propanalyse.com/privacy/ (built by `scripts/more_track.py`).

## Files
```
backend/wrangler.toml          Worker + D1 binding + custom domain + cron
backend/migrations/0001_init.sql  schema (pageviews, clicks, events, submissions, bot_hits, salts)
backend/src/index.js           routes: redirect, beacon, forms, cron
backend/src/admin.js           dashboard, inbox, CSV
backend/src/lib.js             bot filter, device, hashing, sanitisers
backend/src/firms.gen.json     GENERATED by scripts/build.py from data/firms.json (slug -> site / affiliate)
backend/test/*.test.mjs        e2e tests (real wrangler dev + local D1) and site build tests
backend/scripts/seed.mjs       30 days of fake data for the local dashboard
backend/scripts/go-live.sh     verify 302s, then flip the site to TRACK=1
```
`firms.gen.json` is rewritten on every `python3 scripts/build.py`. When an affiliate link goes into `data/firms.json`, rebuild, commit, and `npx wrangler deploy` so the Worker redirects to it.

## Site switch (TRACK flag)
`python3 scripts/build.py` = no tracking (current live site). `TRACK=1 python3 scripts/build.py` =
- every firm Visit / offer / promo / firm-homepage link → `https://go.propanalyse.com/<slug>?src=<page>&pos=<table|offer-card|firm-page|compare|list|cta|text>[&code=PROMO]`, `rel="sponsored nofollow noopener"` when the firm has an affiliate_url, else `nofollow noopener`
- `/assets/a.js` beacon on every page
- complaint + for-firms forms get a "Send to PropAnalyse" button that POSTs to `/f`; the e-mail and GitHub buttons stay as fallback (shown if the endpoint is down)
CI reads the repo variable `TRACK` (and optional `GO_URL`). Flip it with `backend/scripts/go-live.sh` only after the Worker is live; it refuses unless `/ftmo` returns a 302. Rollback: `backend/scripts/go-live.sh off`.

## DNS: getting go.propanalyse.com onto Cloudflare
propanalyse.com DNS is at GoDaddy (ns49/ns50.domaincontrol.com) with only 4 GitHub Pages A records (+ www), no MX/email.

**Option A, recommended: move the nameservers to Cloudflare (free). Least disruptive in practice.**
Registration stays at GoDaddy; only DNS hosting moves. Cloudflare imports the existing records; keep the GitHub Pages records **DNS only (grey cloud)** so the site is served exactly as now by GitHub, certificate included. The Worker then gets `go.propanalyse.com` as a Custom Domain automatically on `wrangler deploy` (DNS record + TLS created by Cloudflare).
1. dash.cloudflare.com → Add a domain → `propanalyse.com` → Free plan.
2. Check the imported records: A `@` → 185.199.108.153 / .109.153 / .110.153 / .111.153 and CNAME `www` → abigailmini.github.io, all **DNS only**. Add any missing.
3. GoDaddy → My Products → propanalyse.com → DNS → Nameservers → Change → "I'll use my own nameservers" → paste the 2 Cloudflare nameservers.
4. Wait for Cloudflare's "active" e-mail (usually under an hour, up to 24 h). Site stays up throughout because both sides serve the same records.

**Option B: keep GoDaddy DNS and CNAME go → <worker>.workers.dev. Does not work on its own.** Cloudflare only runs a Worker on a custom hostname that belongs to a zone in the same Cloudflare account; a foreign CNAME to workers.dev gets error 1014/1001. The workaround (Cloudflare for SaaS custom hostnames) itself needs a Cloudflare zone, so it is Option A plus extra steps.

**Option C, zero DNS change: use the workers.dev URL.** `GO_URL=https://propanalyse-go.<subdomain>.workers.dev backend/scripts/go-live.sh`. Works the same, uglier link, can switch to go.propanalyse.com later (rerun go-live.sh with the new GO_URL).

## Deploy (after `wrangler login` or with `CLOUDFLARE_API_TOKEN`)
```
cd backend
wrangler d1 create propanalyse              # paste database_id into wrangler.toml
wrangler d1 migrations apply DB --remote
wrangler secret put ADMIN_TOKEN             # long random password for /admin
# optional e-mail on new submissions (resend.com, domain verified):
#   wrangler secret put RESEND_API_KEY ; wrangler secret put NOTIFY_TO ; (NOTIFY_FROM default forms@propanalyse.com)
wrangler deploy                             # Option C: comment out `routes` in wrangler.toml first
curl -sI https://go.propanalyse.com/ftmo    # expect 302 + Location: https://ftmo.com/
scripts/go-live.sh                          # flips the site to TRACK=1
```
API token alternative to `wrangler login`: Cloudflare → My Profile → API Tokens → Create → template "Edit Cloudflare Workers", add permission Account · D1 · Edit, zone propanalyse.com → `export CLOUDFLARE_API_TOKEN=...`.

## Free-tier limits
Workers: 100k requests/day. D1: 100k row writes/day, 5M rows read/day, 5 GB. Every page view or click is 1 write. Each dashboard load reads roughly (rows in range × ~20 queries), so at ~1k views/day a 30-day view is ~0.6M reads: fine. Past ~10k views/day, move to Workers Paid ($5/mo, 25B reads) or add nightly roll-up tables.
